# Plans

One file per implementation, named `YYYY-MM-DD-<slug>.md`, usually paired with
a spec of the same slug in `../specs/`.

The spec decides; the plan sequences. A plan lists the steps in order, names
the files each step touches, and says how the result is verified. Its value is
mostly during the work — but a finished plan is also the honest record of what
was actually built versus what was designed.
